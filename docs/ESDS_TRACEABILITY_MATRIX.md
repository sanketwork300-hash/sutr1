# ESDS Traceability Matrix

**Phase 0 deliverable, updated after every phase.** Every requirement in
*ESDS Sovereign Agent Platform — Developer LLD (Condensed Edition v1.1)* appears here exactly once.
Build prompt §85: *"No requirement may disappear simply because it is difficult."*

**Status vocabulary** (build prompt §83, used strictly):

| Status | Meaning |
|---|---|
| **IMPLEMENTED** | Code, API, migration, events, security and tests all exist; tests pass |
| **PARTIAL** | Some of the requirement is real; the remainder is named in *Known limitations* |
| **EXPERIMENTAL** | Exists and runs, but is not relied upon and may change |
| **BLOCKED** | Cannot proceed without external input; the blocker is named |
| **NOT TESTED** | Implemented but never exercised against the real target |
| **NOT IMPLEMENTED** | Nothing exists |

**A note on FR IDs.** The condensed LLD (§1.4) presents the FR-100…FR-1000 map as a graphic; the ten
domain groupings are legible but individual `FR-xyz` identifiers are not enumerated in the condensed
text. Domain-level IDs are used below and marked `(domain)`. Requesting the full FR register from the
LLD authors is tracked as an open item in §14 of this document.

**Baseline for all "Sutr existing capability" claims:** commit `7a89946`, 953 server tests passing,
29 Alembic revisions.
